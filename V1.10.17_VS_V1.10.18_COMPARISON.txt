Localsewa v1.10.17 -> v1.10.18 -> v1.10.19 comparison

Observed from the user-uploaded ZIPs:

v1.10.17 source patch:
- src/screens/customer/AccountSecurityScreen.tsx

v1.10.18 introduced/changed these source areas:
- src/components/account/PasswordSecurityModal.tsx
- src/components/account/index.ts
- src/screens/customer/AccountSecurityScreen.tsx
- src/screens/customer/EditCustomerProfileScreen.tsx
- src/navigation/CustomerNavigator.tsx
- src/navigation/types.ts
- src/screens/customer/index.ts
- src/hooks/useAccountSecurity.ts
- src/api/accountSecurityApi.ts

v1.10.19 restored the old screen routes/hooks/API compatibility, but these four
v1.10.18 source files remained byte-identical:
- src/components/account/PasswordSecurityModal.tsx
- src/components/account/index.ts
- src/screens/customer/AccountSecurityScreen.tsx
- src/screens/customer/EditCustomerProfileScreen.tsx

The release bundle still failed in v1.10.19.

Conclusion:
The physical removal of ChangePasswordScreen / SetPasswordScreen /
ChangeEmailScreen was not sufficient to explain the failure, because v1.10.19
restored them and the release bundler still failed.

The strongest remaining regression surface is the new PasswordSecurityModal
module + its AccountSecurity/barrel integration.

v1.10.20 therefore:
- restores the v1.10.17 Account Security structure as the base
- removes PasswordSecurityModal from the account barrel/module graph
- keeps the old stable password screens/routes internally
- presents those stable password flows inside an inline React Native Modal
- keeps Change Email hidden from the user-facing Account Security UI
- keeps linked email/mobile non-editable in Edit Profile
- keeps Need Help as a text link

No navigation route deletion is performed in this hotfix.
